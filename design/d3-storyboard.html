Navigation rules for every pinned scene

Scroll drives presentation, never content. Everything a scene says is also plain text in the page.

Forward and reverse
Every state is a pure function of scroll position: scrolling back plays the same states in reverse. No one-shot animations inside a pinned range.
Fast scroll
Only the latest scroll position is rendered (one frame per animation frame). A flick past the scene lands on its settled end state; no half-cut frame stays on screen.
Anchors
Each chapter has an id (#laser, #decision, #msc, #ai, #concapp, #publications, #about). A direct link opens the settled end state with its text visible, not the start of the pin.
Skip link
A visible "Skip the cutting sequence" link sits before each pinned scene and moves focus to the next chapter heading.
Keyboard and screen reader
The canvas is aria-hidden decoration with one label. Beat text, the kerf section and the decision diagram exist as DOM content in reading order. Space and Page Down move through the pin at normal scroll speed.
Pause and motion toggle
Scroll-scrubbed motion stops when scrolling stops, so it needs no pause. Anything that runs on its own (hero settle, the MSc "Run example" solver) has Pause / Resume, and a site-wide "Reduce motion" toggle mirrors the OS setting.

Six laser keyframes

Rendered from the motion test's timeline at each beat's settled state. Scroll shares follow the brief: 0–15 approach, 15–25 pierce, 25–60 contour, 60–75 kerf, 75–90 finished profile, 90–100 decision.

Checked against the D0 reference sheet: web horizontal and flanges vertical; nozzle between the flanges; pierce inside the removed part, then lead-in, then contour; one localized cut front; the removed part appears only in a fading exploded view, never lifting itself out. No beam is drawn, so no "beam shown for illustration" caption is needed.
